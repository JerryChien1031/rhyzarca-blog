## 四個入口
- **心得記錄（insights）**：對知識、工具、工作、社會、人機協作與個人經驗的理解、觀察、評析和反思；重點是觀點如何形成與改變。
- **實作探索（practice）**：圍繞具體的製作、應用或改善目標，分享方案構思、可行性研究、設計製作、測試除錯，以及成果與後續改進。不限個人或團隊、軟硬體或創作流程、大型專案或小品，也不以完成或成功為門檻。
- **生活體驗（embodied）**：以親身經歷為主的生活、活動、旅行、學習、工作現場、環境與身體感受。
- **科學思辨（speculations）**：以問題、假說與思想實驗探索科學、技術、歷史或未來社會，討論前提、推論、替代解釋與待驗證之處。

## 實作探索的範圍
可行性討論、需求研究、方案比較、架構設計、團隊專案、個人小工具、學習練習、資料處理、介面或互動作品、AI 工作流程、單元與整合測試、評估實驗、除錯重構、部署維護、交接、操作教學、失敗紀錄與實作回顧，都可以收錄。每篇只談其中一個環節也成立，不要求所有文章都有程式碼或成品。

核心是「想做什麼、處理哪個問題、如何推進或驗證」。規劃尚未開始製作也能是實作探索；但只談文明可能性、引用工程術語，並不自動成為實作。

## 邊界與交集
1. 先看全文的主要目的，再看文風。第一人稱和結語反思不會把實作自動變成心得。
2. 作者未指定分類時，有另一條完整內容主線可保留次要分類，不為增加曝光全選；作者明確指定的單一分類優先。
3. 團隊／個人是合作方式，規劃／原型／已部署是進度，Life World 等是專案，RAG／Agent 等是主題；它們不另立主分類。
4. 「實作探索」不宣稱驗收成功。完成程度、樣本限制、失敗與未驗證事項在正文交代。
5. 指定單一分類的作者要求優先。不得只見 MCP、AI、架構或程式就加上 practice。
6. insights 不刪除、不改作實作的別名；embodied 暫無文章也保留其內容方向。

GitHub、Blogger 導覽、404 分類入口、標籤文字及分類說明同步使用 `_data/blog_categories.json` 的四類定義；Blogger 腳本快照由測試比對。原生分類查詢提示與側欄選中項顯示中文名稱，實際資料仍由相同 canonical label 篩選。分類設定本身的變更也會觸發 Blogger 同步。

分類遷移必須同步更新 Blogger 全站模板的腳本版本，並檢查正式網址。清除 CDN 快取不能使讀者瀏覽器內的舊腳本失效；移除 `architecture` labels 後，舊分類空頁也不會含有文章附帶的 runtime。因此舊入口轉址須由全站腳本完成，不能只依賴文章 HTML 中的補強程式。驗收須包含四類、空分類、舊網址與帶分頁參數的舊網址。

分類與主題標籤使用不同語意。`Epistemology` 仍是既有文章主題標籤，不設定為 `insights` 的自動轉址；未知標籤、外站同名路徑不得改寫。原有主題 tags 不刪除。
